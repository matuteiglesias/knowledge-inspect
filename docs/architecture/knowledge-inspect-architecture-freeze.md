# Knowledge Inspect architecture freeze

**Status:** frozen baseline for the retrofit sequence
**Effective:** PR 1 / Task 1A

This document freezes the smallest current system spine distilled in
`notes/retrofit/knowledge-inspect-architecture-distillation.md`. It is a change
control boundary, not a request for a new framework. Later work may make a
bounded, explicitly approved migration; cleanup must not silently change the
structure or compatibility surfaces below.

## Frozen system spine

1. Four public module CLIs remain: chat ingest, chat analyze, papers/GROBID,
   and chunk-set validation.
2. The three product orchestrators remain independent and share only the
   run-evidence kernel and configuration/path facilities.
3. Chunk-set v1, summary/export output, run record v2, bundle manifest v2, and
   per-operator latest pointers remain public compatibility surfaces.
4. SQLite embedding cache, processed-file ledger, and Chroma integration remain
   private state/recovery machinery with their current ordering guarantees.
5. GROBID and embedding providers remain optional external adapter boundaries;
   their implementation must not own local public identity.

## Frozen invariants

- Every product run attempts to finalize inspectable evidence, including on
  failure.
- Smoke remains provider-independent: it parses a sanitized input and emits
  contract artifacts without credentials, embeddings, Chroma writes, or
  processed-file marks.
- Chunk IDs and Chroma persistence remain deterministic and idempotent.
- Cached vectors are committed incrementally and inputs are marked processed
  only after successful real processing.
- Historical artifacts are immutable. Existing CLI names, options, exit
  meanings, operator identities, artifact paths, and schemas require an
  additive/versioned migration before alteration or removal.
- Analyzer Chroma/mtime fallbacks, compatibility aliases, manual validation,
  and structured diagnostic fields are preserved until an observed,
  separately approved deprecation completes.

## Permitted dependency direction

`CLI -> seam orchestrator -> domain/payload logic -> state or external adapter`

Seams may call the operational evidence kernel. The kernel may use narrow
serialization and path/config primitives, but it must not import seam payloads,
providers, Chroma, GROBID, or CLI code. Reverse dependencies and cross-repository
runtime imports are prohibited.

## Change-control rule

Repository hygiene, deterministic smoke fixtures, characterization tests, and
small boundary isolations are allowed when they preserve the frozen behavior.
Source deletion, public-contract changes, provider/storage migrations, and new
shared abstractions require their own evidence, rollback plan, and explicit
human gate. Generated bytecode is not part of this architecture or distribution
contract.
